2. The problem 0:50 to 1:40

Do: Point at the BLUF box, then scroll to Context.

So here's the problem. Meridian gets about forty thousand scanned claims a month. They want six fields pulled off every page: claim id, policy number, claimant, provider, date of service, and the total. Ninety-seven percent field accuracy. Under two cents a document. And when the system isn't sure, it has to say so instead of guessing, because a wrong payout costs a lot more than a human review.

That last one is the hard one. Reading fields off a scan mostly works now. Catching your own mistakes doesn't. So I built the harness around that.

3. Architecture 1:40 to 3:40

Do: Scroll to 1.1 Flow. Run your finger along the arrow line as you talk.

Here's how it's put together. I write the labels first, from a fixed seed. Then I render each page from its label. So no label ever depends on a model. The extractor sends each page to Gemini with a response schema and gets back one value and one confidence per field, and the value's allowed to be empty. Every raw response goes into a cache that's committed to the repo. The harness scores that cache. It never touches the API.

That split is the main decision. Extraction is one program. Scoring is another. Once the responses are cached, every threshold sweep is free, tuning is repeatable, and the demo you're about to see runs offline and gives the same numbers every time. The cache key is the model, the prompt version, the schema, and the bytes of the image, and both programs recompute it when they read. Regenerate a page and try to score it against an old response, and it refuses. That failure wouldn't crash. It'd hand you plausible wrong numbers. So it gets a check.

Four configurations come out of the same cached calls. One reader on its own. The second reader on its own. A cascade, where a page goes to the second reader when the first one's confidence is low. And double-keying. Both readers read every page, and any field they disagree on goes to a human. That idea comes straight from how claims shops already work. Two people key the same document and a supervisor settles the differences. I automated the control they already trust.

Do: Scroll to 1.3, the trade-offs table.

Now the free tier. My first design escalated to a Flash-class model. Every Flash model I pushed toward evaluation volume stopped after about twenty requests and started returning four-twenty-nines. So the second reader became an independent lite-class model instead. For a disagreement signal, independence matters more than raw capability, so the evaluation survived. The cost is that the cascade has nothing stronger to escalate to. You'll see that in the results.

6. The rule in code 6:50 to 7:40

Do: Tab 5. The highlighted lines are the double-key branch.

Here's the whole idea in ten lines. For each field, take the primary's value and the verifier's value. Normalize both, so a dollar sign or a comma doesn't count as a disagreement. Compare. If they agree, the primary's value goes out. If they don't, the field is marked abstained and goes to the queue. We keep the lower of the two confidences for the record, but nothing depends on it. That's the point. This configuration never asks either model how sure it is.

8. From an eval to a benchmark 9:10 to 10:20

Do: Tab 2. Scroll the README to the dataset table with the five strata.

I built it this way because most of it turns into a benchmark for extraction with abstention. Here's what carries over. A label-first generator with named strata, so the difficulty is designed instead of discovered. A committed response cache, so anyone can reproduce the scoring without spending a cent. A fixed set of metrics: accuracy always shown next to coverage, three kinds of error kept apart, abstention precision from the recorded counterfactual, and an interval on everything. Paired comparison between systems on the same documents, so nobody's comparing overlapping error bars. And reconciliation, does the itemization add up to the total, because adjudication is the job underneath the transcription.

The findings tell you what a benchmark like that has to contain. Out-of-distribution pages that bait a hallucination, because that's where the two readers split. Degraded scans, because that's the only stratum with errors in it. And the thing you report should be the whole cost-accuracy frontier rather than one number, because Meridian's decision is a trade between coverage and review load. What's missing is real documents. The synthetic failure distribution is my guess at theirs.

If they ask

Short spoken answers. Know these without notes; the committee's hire signal depends on it.

QuestionAnswer
Why labels before documents?If labels come from a model, you're measuring agreement with that model. Writing the label first and rendering the page from it means the truth is independent of anything being tested, and I can regenerate the corpus byte for byte from the seed.
Why Wilson intervals?My proportions sit near 1.0 with n between 40 and 240. The normal approximation gives intervals that go above 100 percent there. Wilson stays inside 0 to 1 and behaves at small n.
What is the paired comparison doing?Every configuration is scored on the same documents, so the difference is paired. McNemar's exact test counts the instances where one system was wrong and the other right. The bootstrap resamples whole documents, because six fields on one page share the same scan and aren't independent.
Why did the cascade collapse to zero?The objective maximises coverage subject to the 97 percent bar, tie-break on cost. Escalation doesn't change coverage and adds cost, and on tune it never raised accuracy because the second reader isn't stronger. So zero was the right threshold for these two readers.
What's in the cache key, and why not the prompt text?Model, prompt version, schema hash, image hash, run index, temperature tag. The prompt text isn't hashed in because changing it would orphan the committed cache, so a test pins the prompt's hash to its version and fails if the text changes without a bump.
What would you watch in production?Disagreement rate against its 3.3 percent baseline, daily. Adjudicator rulings on flagged items, which make abstention precision a live number. A weekly re-score of two hundred documents through the same harness, with a stop on auto-pay if the lower bound drops under 97. And the model version string, because the name is an alias.
Why not just pay for the API?I could have, for a few dollars. I kept the free tier because it's what a partner's evaluation actually runs on first, and hitting the quota wall produced the most useful friction item in the log. I'd re-run the cascade on a paid tier with a Flash second reader; that's next step two.
How much of this did the AI do?Claude wrote most of the code with me directing; Claude and Gemini drafted the documents. The design decisions, the metric choices, the double-keying idea, and the decision to report the negative results are mine, and I can walk any line of the harness.
