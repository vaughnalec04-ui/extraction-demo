Scope
Meridian is a composite partner profile built for this exercise. The corpus is synthetic: labels were written first and each page rendered from its label, so no label depends on a model. Its failure distribution is a guess about theirs.

Bottom line

Meridian receives about 40,000 scanned claims documents a month. It needs six payment-critical fields read at 97% field accuracy, under $0.02 a document, by a system that flags what it is unsure of. On a corpus built to their failure modes:

  • Accuracy is met with no margin. One lite-class reader, gemini-3.5-flash-lite, reads 99.2% [97.0–99.8] of fields correctly with no abstention at $0.00132 a document. The lower bound is the bar.
  • Two readers double-keyed reach 100% [98.4–100] on the 96.7% of fields they agree on, at $0.00221. Disagreements go to review, the control Meridian's own processors already run. On the same documents the two systems differ on two field-instances (p = 0.50); what this sample establishes is the 3.3 points of coverage the second reader costs.
  • Cost is not the constraint. The dearest configuration is about a ninth of the budget. Quota is: on this tier, 40,000 documents is 83 hours of continuous running with no headroom.
  • Knowing when it is unsure is the open requirement. Self-reported confidence is near-constant, 1.0 on all 240 instances for one reader, and cannot gate anything. Disagreement between readers is the one signal that carried information: of 8 flags, 2 were real errors. A precision of 25% [7.1–59.1] is not a number to build on yet.

Recommendation. Run this harness unchanged on 500 of Meridian's own documents, weighted toward the exceptions their contractors already flag, before choosing a configuration. The gates are in section 2.

1Architecture: design, flow and trade-offs

  1. LabelsAuthored first from a fixed seed: six fields, line items, stated total.
  2. DocumentsRendered from the labels. Five strata; scanner noise and JPEG loss on every page.
  3. ExtractorGemini structured output against a response schema: a nullable value and a confidence per field.
  4. Response cacheEvery raw response, keyed on model, prompt version, schema and image bytes. Committed.
  5. HarnessScores the cache offline. Four configurations from the same calls. Never calls the API.

Extraction and scoring are separate programs. Thresholds are chosen from cached responses, so sweeps cost nothing, tuning is reproducible, and the demo replays offline with identical numbers. The cache key is recomputed on every read, so a regenerated page cannot be scored against an old response: that failure does not crash and produces plausible wrong numbers.

Four configurations are resolved from the same cached calls: the primary reader alone; the verifier alone; a cascade that sends a page to the verifier when the primary's own confidence is low, the standard cost saver; and double-keying, both readers on every page with disagreement routed to review, which needs no self-assessment from either model.

2Evaluation: define, measure, monitor

Define

  • The unit is the field-instance, one field on one document, because Meridian pays per field. Exact and normalized match are both reported and never merged.
  • Three error kinds, never pooled, because their costs differ: a wrong value is a wrong payout, a missed field is a rekey, a hallucinated field is a payment on a page that is not a claim.
  • Accuracy is never shown without coverage. Abstention precision uses the recorded counterfactual for every flag: what would have gone out without it.
  • Calibration in ten confidence bins with expected calibration error, flagged degenerate when one bin holds the predictions. Wilson 95% intervals on every proportion.
  • Configurations are compared paired, on the same documents: McNemar's exact test on discordant instances, and a bootstrap that resamples documents, since six fields on one page share one scan.
  • Reconciliation, whether the line items sum to the stated total: the adjudication under the transcription, where a processor loses money.

Protocol: 80 documents in five strata (clean 24, ambiguous 16, degraded 16, incomplete 16, out-of-distribution 8), split 40 tune and 40 test before the first API call. Thresholds were swept on tune only. Test was scored once.

The cascade had nothing to escalate to. Tuning set its escalation threshold to zero, so on test it is the primary alone. On tune no threshold raised accuracy, and escalating every page lowered it from 98.75% to 97.92% at 1.7 times the cost: the second reader is not stronger. The primary's confidence is 1.0 on 214 of 240 instances, yet its two test errors were its two lowest confidences, 0.90 and 0.95, on one degraded page. Five errors decide nothing about the signal. A cascade needs a stronger second reader before the trigger matters.

Double-keying earns its cost on hallucinations. Alone, the verifier invented five values on out-of-distribution pages, reading a utility bill's "Amount Due" as a claim total. Under double-keying none reached output. The primary was right on those pages, so here the flags were review cost; with the roles reversed they would have been saved payouts. On total_amount, the payment field: primary alone 97.5% [87.1–99.6], double-keying 100% [90.8–100].

Reconciliation. 34 test documents carry an itemisation and a stated total; 12 are inconsistent by construction. The primary caught all 12 [75.8–100]; the verifier missed one, a claim that would have been paid. Model arithmetic was correct on every document; every verdict failure is a misread digit on a degraded scan (line items read correctly 91.2% [77.0–97.0]).

Not established. 240 field-instances and 8 flags are small. This corpus has one complete run; three runs on the previous corpus moved accuracy 0.4 points, so treat any figure as ±0.4. Calibration cannot be shown with 239 of 240 predictions in one bin. The degraded stratum is the only one below 100% for the primary (95.8% [86.0–98.8]) and where double-keying's coverage drops most (93.8%; 79.2% on out-of-distribution pages).

Monitor

Per document, the pipeline already emits: reader disagreement by field and stratum; each flagged item's adjudication outcome, which makes abstention precision a running measurement; cost from usage metadata; p50 and p95 latency with the 429 and 503 rate; and the model version string. Proposed for Meridian to confirm:

  • Daily. Disagreement rate against its baseline of 3.3% of fields. Above twice baseline, someone is paged: the input mix moved or a model changed.
  • Weekly. Re-score a 200-document sample with this harness unchanged, adjudicators' final values as labels. Human-check 2% of agreed items: agreement between two readers is the one error the system cannot see.
  • Gate. Accuracy on covered, lower bound, at or above 97% on the weekly sample. Below it, automatic payment stops and the queue takes everything until the cause is found.
  • Model change. The model name is an alias. Any change in the returned version re-runs the harness on the committed corpus before the next batch.
  • Pilot gates for the 500-document run: lower bound at or above 97% on covered; coverage at or above 90%, set against the queue's capacity; at least one flag in three a real error. If double-keying misses the last gate, the primary alone with sampled audit is the honest alternative.

Throughput is bound by quota, not client code: about 8 documents a minute from 1 to 8 workers and 12% slower at 16, behind one shared rate gate. The Batch API is the right mode for overnight bulk at half the price; batches.create failed a precondition on this tier (F-011), so no batch figure is claimed.
